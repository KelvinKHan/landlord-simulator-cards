# 发布步骤

玩家入口通过 GitHub `/releases/latest` 发现正式版，按版本标签从 jsDelivr 读取 `dist/release.json`、`runtime.js` 和 `content.json`。单纯 push 主分支或上传候选版，不会自动改变玩家正式版。

## 新版本

1. 修改 `src/`，运行 `npm run release:prepare -- 5.21.0`（版本号按实际版本替换）。该命令更新版本、构建并执行完整自动检查，拒绝覆盖已有标签。
2. 对重要运行变更执行 `npm run test:integration`，并更新验收记录。
3. 提交源码、`dist/`、`exports/` 和测试记录，推送仓库；为同一提交创建 `v5.21.0` 标签并推送。
4. GitHub Actions 的 **Prepare release draft** 手动工作流接收该标签，重新检查构建结果及文件校验，创建带卡文件的草稿 Release。
5. 作者验收后，在 GitHub 发布该草稿。正式版标签必须是 `vX.Y.Z` 且取消“预发布”；候选版 `vX.Y.Z-rc.N` 保持预发布状态，不进入玩家自动发现。
6. 运行 `node tools/release/verify-cdn.mjs v5.21.0`，从公开 jsDelivr 下载清单、入口、运行包、内容包和两份卡，核对与仓库字节一致及跨域响应头。CDN 尚未准备好时，旧玩家会使用缓存，下次启动再检查。

已发布标签不可挪动，已发布产物不就地覆盖。回退线上错误时优先发布更高修订版本；客户端不会主动降级到比成功缓存更低的正式版本。

## 当前交付

`5.21.0-rc.2` 是供作者验收的候选版，完整卡和脚本位于仓库 `exports/`；分发状态以 [验收记录](testing/README.md) 中的标签与 CDN 核验结果为准。本版移除大富翁及分基地相关定义、世界书段落和新卡开场说明，保留原卡与三方合并基线。参见 [移除范围](removing-monopoly.md)。

候选版入口保留跟随未来正式版的能力，但 `rc.2` 不会通过正式版检查自动送达 `rc.1` 玩家。试用时导入本版完整卡或单入口脚本；新版首条开场需要完整卡与新聊天，脚本更新不会改写既有聊天开场。正式发布前继续验收建造、招募、档案保存和实际副 API 返回的表现。
