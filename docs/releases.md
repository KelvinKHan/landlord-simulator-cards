# 发布步骤

玩家入口默认通过 GitHub `/releases/latest` 发现正式版，按版本标签从 jsDelivr 读取 `dist/release.json`、`runtime.js` 和 `content.json`。版本面板通过公开 Release 目录提供手动固定版本，公开候选版可以手选，草稿不会进入目录。单纯 push 主分支或发布候选版，不会自动改变玩家正式版。

## 新版本

1. 修改 `src/`，运行 `npm run release:prepare -- 5.21.0`（版本号按实际版本替换）。该命令更新版本、构建并执行完整自动检查，拒绝覆盖已有标签。
2. 对重要运行变更执行 `npm run test:integration`，并更新验收记录。
3. 提交源码、`dist/`、`exports/` 和测试记录，推送仓库；为同一提交创建 `v5.21.0` 标签并推送。
4. GitHub Actions 的 **Prepare release draft** 手动工作流接收该标签，重新检查构建结果及文件校验，创建带卡文件的草稿 Release。
5. 作者验收后，在 GitHub 发布该草稿。正式版标签必须是 `vX.Y.Z` 且取消“预发布”；候选版 `vX.Y.Z-rc.N` 保持预发布状态，发布后进入手选目录，仍不进入玩家自动更新。只有标签、仍为草稿的版本不会因此出现在公开目录中；入口默认版和玩家已知版本另行保留为本地选项。
6. 运行 `node tools/release/verify-cdn.mjs v5.21.0`，从公开 jsDelivr 下载清单、入口、运行包、内容包和两份卡，核对与仓库字节一致及跨域响应头。CDN 尚未准备好时，旧玩家会使用缓存，下次启动再检查。

已发布标签不可挪动，已发布产物不就地覆盖。回退线上错误时优先发布更高修订版本；正常跟随正式版的客户端不会主动降级到比成功缓存更低的正式版本。玩家可以明确固定旧版本；从固定版本改回“跟随最新正式版”时，允许回到实际最新正式版。

发布应继续保持当前清单 `format: 1` 及运行包接口兼容。普通脚本与官方世界书更新由现有入口获取，无须让玩家逐次导入整张卡；修改入口协议、正则、首条开场或人物资料时，需要在发布说明中说明是否仍须更新入口或完整卡。版本回退不等于存档回退，不能承诺较旧脚本无条件兼容较新存档。

## 当前交付

`5.21.0-rc.5` 是供作者验收的候选版，完整卡和脚本位于仓库 `exports/`；分发和检查状态以 [验收记录](testing/README.md) 中的具体版本、标签与 CDN 核验结果为准。本版把版本入口改为可拖动并记忆位置的悬浮球，点击展开、拖动不误开，展开面板自动适应屏幕边缘；版本选择、校验和刷新流程继续保留。此前的大富翁、分基地清理继续保留，原卡与三方合并基线保持历史内容。参见 [移除范围](removing-monopoly.md)。

`rc.1`–`rc.4` 玩家需替换本版单入口一次（也可导入完整卡）并刷新酒馆，才能获得版本悬浮球；较旧入口不会通过普通运行包更新获得这项入口界面变化。`rc.5` 入口默认版本始终可选，即使该 Release 尚为草稿。此后兼容格式的普通脚本和官方世界书更新可直接在卡内选择，无须逐版导入卡。

新版首条开场仍需完整卡与新聊天，脚本更新不会改写既有聊天开场。正式发布前按 [版本选择说明](version-selection.md) 验收保存偏好、刷新生效、固定旧版与恢复跟随，并继续验收建造、招募、档案保存和实际副 API 返回的表现。
