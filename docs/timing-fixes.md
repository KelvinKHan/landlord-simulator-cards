# 本轮修复范围

本轮依据作者授权处理时序隐患、单入口及版本更新。以下状态针对新源码和候选卡；Z5.20 原始备份及其旧分析保持历史含义。

当前候选版为 **5.21.0-rc.2**，在时序修复基础上进一步完成作者要求的大富翁清理。新变量结构、世界书及新卡开场不再包含大富翁或分基地；原卡和旧升级基线保留，旧存档不主动擦除。详细边界见 [大富翁移除范围](removing-monopoly.md)。

| 问题 | 新版处理 |
| --- | --- |
| 脚本按独立 iframe 和固定延迟碰运气启动 | 一个真实酒馆助手 iframe，依赖显式排序；数据库提交与就绪后再加载依赖应用 |
| Zod / MVU 注册先后和重复注册 | 结构监听先注册，MVU 后启动；结构监听归属于可清理作用域 |
| 聊天切换、删消息、切换分支后旧任务继续执行 | 聊天与分支代次检查，取消网络、定时器和待启动任务，旧作用域禁止写回 |
| 启动中途切换导致初始化永久等候 | 就绪等待可取消，切换队列不被旧初始化阻塞 |
| 重复初始化清空调度器、重复事件订阅 | 初始化幂等，依赖按顺序注册，监听和全局对象成对清理 |
| 两个会话同步时第二个任务被丢弃 | 同步排队；真正返回写入结果，成功后才标记已同步 |
| 多个模块更新同一世界书时相互覆盖 | 所有内部模块的世界书更新共用按书名分组的串行队列 |
| 撤回最后一条消息留下摘要 | 空会话删除原摘要；删除、清空与同步经过同一队列 |
| 保存消息和列表摘要先后不一致 | 消息与会话摘要在同一个 IndexedDB 事务中提交 |
| 发消息等待期间切换通讯录 | 原版发送先捕获会话身份，后续保存和刷新使用该身份 |
| 二改调度器超时后旧请求未结束就重试 | 请求超时负责取消整个响应体；任务结束后才允许重试，取消不重试 |
| 新闻排队期间连点产生多份任务 | 入队前锁定，同一任务键去重，最终完成或失败后释放 |
| 分析尚未成功就推进完成楼层 | 整批分析确认成功后才记录进度，部分失败保留重试位置 |
| 多种消息事件反复重绘覆盖编辑 | 统一串行重绘；候选/档案内容不变时保留选择、编辑和按钮状态；MVU 增删状态占位符不误判为新档案 |
| 原版公寓未打开时获取不到卧室 | 两版使用同一个实时 MVU 卧室查询桥，脱离界面缓存 |
| 天气优先读过时变量或不完整补丁 | 优先从当前 MVU 完整状态读取日期和小时 |
| 二改公寓调用不存在的初始化函数 | 移除孤立调用，接通已有 MVU 监听和真实渲染链 |
| 工坊修改开场删除变量、伪造聊天事件 | 使用真实 MVU 解析与替换接口，消息/变量备份、失败恢复和中断记录 |
| 新包与世界书版本混装、更新失败停在半成品 | 固定版本清单、完整性检查、三方合并、缓存回退及事务恢复 |

原版加载 S02、S04、S06–S23 中适用的 20 个模块；二改版加载 S02、S25–S29、S23，共 7 个。S01 的结构注册与 MVU 为公共依赖。S03 的旧开关器由统一选择器替代，S05 示例和 S24 大富翁没有纳入开发源码；S01 的大富翁与分基地字段也已删除。内部仍保存两版实现，未把二创改写为原版。

## 尚未处理的业务问题

这些不属于本轮启动和异步时序修复，不能把本轮通过的测试理解为旧分析所有问题都已解决：

- F01：上游 Zod 工具会重建顶层对象，顶层租客/房间一致性 refine 的事务设计尚待单独处理；不能直接恢复为逐补丁强校验。
- F02 / F10 / F16：二改天气字段和原版天气缓存协议仍不同，幻想年份到气象日历的规则未代定。
- F05：旧手机导入覆盖流程的完整数据校验和整包迁移尚未重做。
- F06：原正则过滤多个更新块的贪婪匹配未改，本轮保留正则内容与设置。
- F08 / F09 / F11：档案与入住阶段、人名改名关联、世界书规则冲突和副模型知情范围，仍需产品规则设计。卧室实时读取已修。
- F13：API 配置日志已去掉敏感配置对象，但原代码的所有 HTML、slash 拼接和消息桥安全审计未纳入本轮。
- F16 / F17：两版的正文标签协议、手机记录迁移与共享记忆策略未统一；选择二改版不等于历史自动迁入二改数据库。
- F18 / F20：工坊世界观自动继承、附加世界书条目归属、预设六租客固定档案和地图旅行短语仍维持原行为。开场消息/变量事务已修。

大富翁相关 F19 不继续开发。未接入玩家真实配置、真实聊天或付费模型；已验证的上游版本之外仍可能有兼容性差异。
